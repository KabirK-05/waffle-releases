# Waffle

Waffle is an original macOS overlay assistant (Electron, plain JavaScript, no bundler or framework). A hotkey captures the screen, the screenshot and question go to Claude, and the answer streams into an always-on-top overlay. Listen mode adds a transcript of recent microphone and system audio.

The folder is named `CrackedCluely` for historical reasons; the app is called Waffle.

## Ground rules

- **Never commit or print API keys.** Keys live encrypted in the app's user-data folder, not in the repo.

## Commands

```bash
npm install     # dependencies; also builds bin/waffle-speech, universal (needs the Xcode CLT)
npm run build:speech   # rebuild the on-device speech helper after editing native/waffle-speech.swift
npm start       # run the app (electron .)
npm run dist    # signed, notarized universal DMG + update ZIP in dist/ (unsigned without a Developer ID)
npm run release # the same, uploaded to the GitHub release that installed copies update from
node --check main.js   # there is no test suite or linter; syntax-check edited files
```

Node 22+ is required. On this machine the default Node is older, so prefix with `fnm exec --using=24` (for example `fnm exec --using=24 npm start`). Use the Apple Silicon Homebrew at `/opt/homebrew/bin/brew`; the default `brew` on PATH is a stale Intel install.

## Layout

- `main.js`: main process. Windows, shared state, global shortcuts, screen capture, tray, Claude streaming, IPC handlers.
- `providers.js`: subscription billing. Drives the user's signed-in `claude` (Claude Code) and `codex` (Codex CLI) in headless mode; `state.provider` picks `api`, `openai`, `claude` or `chatgpt`. Waffle never touches those tools' OAuth tokens; sign-in opens the tool's own login command in Terminal. Waffle never signs the tools out: Disconnect (Account → Manage connected accounts) adds the provider to the persisted `state.disconnected`, and `applyAuth()` then reports it as `signedIn: false, disconnected: true`, so every `signedIn` check means "Waffle may use it"; Connect removes it again in one click. Claude runs as one long-lived `claude -p` process per conversation (stream-json in and out), started ahead of the first question and closed on New Chat and quit; Stop sends an interrupt so the conversation survives. Codex still runs one process per question. `complete()` is a one-off answer in its own process (session summaries), so it never disturbs the live chat process.
- `openai.js`: the `openai` provider (OpenAI API key). Streams answers from the Responses API with plain `fetch`, converting Waffle's Anthropic-format history to Responses input; also `complete()` for summaries and `listModels()`. It uses the same key as the speech fallback (`speechKeyEnc`), so there is one OpenAI key. `state.openaiModel` empty means the newest GPT-5 model the key can list.
- `prompts.js`: the system prompt in layers: `BASE` (hidden rules), each built-in mode's hidden `prompt`, its visible first-person `context` (editable in Settings → Modes), then reference-file text and the follow-up format. Also the default question sent when the user asks nothing, and the session-summary request (`meetingSummary()`, `parseMeetingSummary()`).
- `modes.js`: `ModeStore`, built-in plus custom modes (`state.mode` may be a `custom-…` id). Saves edited contexts and custom modes to `modes.json` and attached files to `mode-files/` in user data. Text, Markdown, code, .docx and .pptx become text in the system prompt; PDFs go to the API and Claude Code as document blocks and to Codex as files in its work folder. General has no context or files. `list()` leaves out the hidden prompts so renderers never see them.
- `history.js`: saved conversations and listening sessions in `history.db` (Node's built-in `node:sqlite`, no native module). Text only; screenshots and audio are never stored. A session is a `sessions` row with `kind = 'meeting'`, its summary and its transcript as JSON (`saveMeeting()`). `state.currentChatId` is the saved chat on screen; `keepHistory` turns saving off.
- `audio.js`: microphone capture (`waffle-speech --mic`), system-audio capture (audiotee, run from outside the asar via `AUDIOTEE_BIN`), and `LiveTranscriber` (one per speaker) that turns each stream into text as it is heard, on device or through the speech API.
- `native/waffle-speech.swift`: a command-line helper for Apple's on-device engine (SpeechAnalyzer, macOS 26+). `--stream` reads raw PCM on stdin and writes partial and final results as JSON lines; `--check` reports whether it can run; `--mic` records the microphone (AVAudioEngine, macOS 14+) as raw 16 kHz PCM on stdout until stdin closes, which replaced sox so the downloaded app needs nothing from Homebrew. `scripts/build-speech.js` compiles it to a universal `bin/waffle-speech` (gitignored); a packaged build keeps it outside the asar archive (`asarUnpack`).
- **Packaging and updates** (`electron-builder.config.js`, `scripts/dist.js`, `build/entitlements.mac.plist`, `docs/releasing.md`): a universal, hardened-runtime app signed with the Developer ID certificate and notarized with credentials from the gitignored `.env.release`; DMG for download, ZIP + `latest-mac.yml` for updates, published to the public `KabirK-05/waffle-releases`. Helpers inherit the entitlements (waffle-speech needs `device.audio-input`). `updater.js` wraps electron-updater: packaged builds only, checks after launch and every 4 hours, downloads in the background, installs on quit or from Settings → General → Software Update; its status is the volatile `state.update`.
- `preload.js`: the allow-listed bridge exposed to renderers as `window.waffle`. Renderers never get raw `ipcRenderer`.
- `renderer/index.html`, `renderer/app.js`, `renderer/styles.css`: one renderer bundle for every window. The hash route (`#control`, `#chat`, `#settings/<section>`) picks the view.
- `renderer/onboarding.html`, `renderer/onboarding.js`, `renderer/onboarding.css`: first-run setup in its own 1100 × 720 window, a copy of Cluely's onboarding without its account sign-in. Steps (`ONBOARDING_STEPS` in main): welcome, choose and sign in to the Claude or ChatGPT subscription, permissions (microphone, system audio, screen), then demos of ask, hide, move, listen, notes and undetectable. The permission dialogs, the System Settings list and the ask demo's video editor are drawn in HTML and CSS (`macAlert()`, `settingsList()`, `editorScreen()`; `.ob-mac-*`, `.ob-ed-*`), not pictures; the demos' video call is drawn in HTML around two generated webcam clips (`call-1.webm`, `call-2.webm`); the pages use the same `app-mark` icon wherever Cluely shows its logo.
- `assets/icon.png`, `assets/icon.icns`: Waffle's app icon (macOS rounded-square grid). `app.dock.setIcon()` uses the PNG so a dev build shows it instead of Electron's; the `.icns` is for a packaged build.
- **Account Settings** (`accountPane()` in `renderer/app.js`, opened from the profile card at the top of the Settings sidebar, like Cluely's): your name (`profileName`, defaulting to the Mac account's full name) and photo (`profile-photo.png` in user data, 256px, served to the page by `profile-photo-get`), plus the connected subscriptions and API keys. General keeps only the provider and model choice for answers.
- `usage.js`: subscription limits for the Account page's Usage section. Claude Code's stream-json `rate_limit_event`s (5-hour and weekly utilization, reset times) and Codex's own session log (`~/.codex/sessions/…/rollout-*.jsonl`, `rate_limits`), since `codex exec --json` doesn't carry them. Neither reads the tools' tokens. `providers.onUsage()` reports them; main keeps the latest in the persisted `state.usage`.
- `web/`: the landing page (Next.js, its own `package.json`); `web/lib/links.ts` holds the GitHub and download links.
- `renderer/markdown.js`: a small Markdown renderer that escapes HTML before adding markup.
- `renderer/highlight.js`: an approximate syntax highlighter for answer code blocks; builds DOM nodes from text, never HTML.

## How it fits together

- **First run.** Until `state.onboarded` is true, main opens the setup window (`openOnboarding()`) instead of the overlay, and no global shortcuts are registered while it is open (the demos read ⌘\ and ⌘arrows in the page). `onboardingStep` is persisted so setup resumes after the Screen Recording relaunch. Saved state from before this flag existed counts as onboarded. Settings → General → Reset onboarding (the footer, as in Cluely), or the tray, opens it again.
- **Three windows.** A control pill, a chat window docked 6 px beneath it (it resizes to its content through `chat-window-resize`), and a regular settings window.
- **Shared state.** The main process owns one state object. `DEFAULT_STATE` fields are persisted to `shared-state.json` in user data; `VOLATILE()` fields are memory-only. `patchState()` applies a change, runs side effects in `applyState()`, and broadcasts `shared-state-updated` to every window. Renderers change state only through `patch-shared-state`, which is filtered by `RENDERER_PATCHABLE` and validated by `sanitize()`. When adding a setting, update all of those.
- **Hiding from capture.** `applyWindowPolicies()` sets content protection on every window when `isInvisible` or `isCapturingScreenshot` is true, so the overlay never appears in its own screenshot.
- **Shortcuts.** `state.shortcuts` maps action names to accelerators; `registerShortcuts()` unregisters everything and registers the map again on each change. Actions are in `ACTIONS`. Global shortcuts are released while `isRecordingShortcut` is true. The ask shortcut (⌘↵) is the exception: `syncAskShortcut()` holds it only while the overlay is on screen, so other apps get ⌘↵ while Waffle is hidden.
- **Ask flow.** Hotkey → main sends `chat-submit` → the chat renderer invokes `capture-screenshot` (returns an id; the PNG stays in main) → renderer sends `chat-send` → main optionally transcribes audio, calls Claude, and streams `chat-stream-*` events back.
- **Follow-ups.** With `state.followUps` on, the system prompt asks the model to end each answer with a hidden `<followups>` block. `prompts.splitFollowUps()` strips it in main (history saves only the visible answer) and the options go out with `chat-stream-done`; the renderer hides the block while streaming and shows numbered options. Their hotkeys (`followUp1`–`followUp3`, default ⌘1–⌘3) are registered by `syncFollowUpShortcuts()` only while options are on screen, never in `registerShortcuts()`, so they don't take ⌘1 from other apps.
- **Listening sessions.** `AudioCapture` records `me` (the mic, `waffle-speech --mic`) and `them` (system audio, `audiotee`) at 16 kHz mono and hands each chunk to that speaker's `LiveTranscriber`. With `state.speechEngine` `apple` (the default) the transcriber runs `bin/waffle-speech --stream`; if the helper fails and a speech key is saved it switches to cutting phrases at pauses and posting them to the OpenAI-compatible endpoint, and `audioNotice` says so. Results build `session` in main (entries plus each speaker's in-progress partial), pushed to the overlay as `transcript` events (throttled). Starting a session opens the overlay's transcript view; the toolbar swaps the listen button for pause, stop and a timer (`listenPaused`, `listenClock`). `session` in main is the session in focus. Stopping keeps it on screen, saves it (`meetings` in memory for this run, plus history.db when `keepHistory` is on) and asks the selected provider for a title and summary in the background (`summarizeMeeting()`). A finished session's transcript and summary are black pages with its title and chips, and a session bar (Back, Show Summary/Transcript, Resume session) in place of the toolbar. Back (`closeMeeting()`) or New Chat takes it out of focus; History lists sessions next to chats and opens them on the summary (`openMeeting()`); Resume continues the same session, offsetting new timestamps by its duration, and re-summarises when stopped again. Each question carries only the transcript lines not yet sent in this chat (`transcriptForQuestion()`); New Chat marks them unsent again. `state.appleSpeech` holds the helper's status, checked at launch with `--check`.

## Things that will trip you up

- **You cannot screenshot the overlay.** Content protection is on by default, so visual checks need the user, or `isInvisible` turned off in settings.
- **macOS permissions** (Screen Recording, microphone, system audio) apply only after a relaunch, and in development are attributed to Electron or the launching terminal app.
- **The Claude call** uses `client.beta.messages.stream` with model `claude-opus-5-5`, `output_config.effort`, and server-side refusal fallbacks. Read the current Anthropic SDK docs before changing request parameters.
- **CSP** in `index.html` allows only same-origin scripts, styles and fonts: no inline scripts, no inline styles, no remote assets. Style attributes in inserted HTML are blocked too, which is why maths is rendered by `renderMath()` (KaTeX building DOM nodes) after the Markdown HTML is inserted, not with `katex.renderToString`.
- **KaTeX** is vendored in `renderer/vendor/katex/` (0.19.1, MIT; woff2 fonts only). The base prompt asks the model to write all maths, including big-O, as `$…$` / `$$…$$`.
- **Secrets** are written through `writeSecret()`, which merges into `secrets.json`; do not overwrite that file wholesale.
- `openAtLogin` is applied only in a packaged build, to avoid registering the bare Electron binary as a login item.
